# 用同一份简报盲评两个版本

编辑记录哪篇愿意发布、首稿是否已可确认，以及实际花了几分钟修改。运营实拍海外稿时，也可记下需要重拍的镜头。下列工具只读取本地已经生成的稿件，编排对照、保存编辑评分并汇总。可从提示词、模型或生成策略中选一项作为一轮的变量。

## 先试一次回放

在仓库根目录运行以下命令。示例使用仓库归档的一份虚构商家简报与真实模型首稿，A、B 是同一篇。用于熟悉评审，不提供质量提升或人工评分数据。[样稿原始记录](examples/open-desk-saturday.json)

```sh
python3 scripts/blind_review.py example /tmp/daolook-review-example
python3 scripts/blind_review.py report /tmp/daolook-review-example/private-key.json /tmp/daolook-review-example/ratings.csv
```

打开 `review.txt` 阅读，使用电子表格程序以 UTF-8 打开 `ratings.csv`，填写后保存为 CSV，再运行第二条命令。新一轮请指定新目录，已有评审材料会被保留。

## 准备真实试点

可下载一份空白简报，填入业务事实后开始第一轮。模板中的平台和目标可调整。[空白商家简报](examples/商家简报模板.json)

1. 由试点商家逐份提供可供评审的脱敏简报。第一轮建议积累 30–50 份，有了第一份就可以试用。每个商家只用一个稳定代号，避免不同门店名把同一商家拆进训练和留出两组。材料覆盖小红书和抖音的曝光、咨询、下单目标，也应包含无购买入口、价格冲突、缺关键材料的简报。海外拍摄案例在简报中写明人数、场地、道具。
2. 在 `briefs.json` 中放一个数组，每份简报包含 `id`、`merchant`、`origin` 和 `input`。真实业务用 `business`，练习用 `fixture`，分别成组。以下字段模板可直接替换，所有放进 `input` 的内容都会给编辑看。

```json
[
  {
    "id": "brief-001",
    "merchant": "shop-01",
    "origin": "fixture",
    "input": {
      "platform": "xhs",
      "goal": "sales",
      "topic": "填写脱敏产品或主题",
      "temporary": "填写已核实的业务资料原文",
      "requirements": "填写目标受众、约束或拍摄条件"
    }
  }
]
```

3. 用同一目录冻结本轮分组；调试人员只拿开发组。默认按商家随机留出约四分之一，固定种子可复现。多个简报属于同一商家时会整组入选。只有一家时默认全进开发组。需要固定某些商家时，可重复传入 `--holdout-merchant 商家代号`。追加商家后应开始新一轮或显式沿用既定留出名单。

```sh
python3 scripts/blind_review.py split briefs.json runs/round-01
```

4. 现版与候选版都从同一份冻结输入生成。每份保留完整输入、输出顺序与版本标识，统一评审批次里的第一篇，避免任一版本事后挑最好的一篇。评估时先用开发组调整，定版后保管人再使用留出组。重新调用模型的运行记录应保留费用、重试和用量，评审工具本身不发起模型请求。

**有生成归档时**，每个文件保存一个简报的一批输出，形状与仓库的 `open-desk-saturday.json` 一致，即 `{"input": {...}, "outputs": [...]}`。工具以归档实际输入计算指纹，要求与分组时冻结的输入完全相符。一份输入对应多个简报编号时，在归档中补相应 `id`。生成失败的批次保留 `input`，提供 `failure` 原因，`outputs` 留空。可选的 `usage` 见下节。

```sh
python3 scripts/blind_review.py capture runs/round-01/holdout.json runs/round-01/baseline.json captures/old/*.json --version old-v4
python3 scripts/blind_review.py capture runs/round-01/holdout.json runs/round-01/candidate.json captures/new/*.json --version new-v5
python3 scripts/blind_review.py prepare runs/round-01/holdout.json runs/round-01/baseline.json runs/round-01/candidate.json runs/review-01
```

**只有可发布文案时**，分别复制 split 生成的 `holdout.responses.json`，填写不同的 `version`，在每个编号的 `draft` 中粘贴第一篇完整成品文字或 Daolook 稿件对象。由保管人确认记录来自对应冻结输入，保留输入指纹。失败时 `draft` 填 null、`failure` 写明原因。然后执行上面的 prepare。每个版本都需交回所有编号，由此保留生成失败的分母。

## 编辑怎么评

每次 prepare 都会打乱简报次序，给每个简报生成匿名编号并随机交换两版左右位置。保管人仅向编辑提供 `review.txt` 与 `ratings.csv`，自行保存 `private-key.json`。每份简报的两行评分各对应 A 或 B。未审、未做实拍或未计时的字段留空。

| CSV 列 | 填写规则 |
| --- | --- |
| 愿意发布 | 经本次编辑之后愿意发布填 1，弃用填 0。 |
| 首稿可确认 | 初稿可直接确认发布填 1，需改或弃用填 0。 |
| 编辑分钟 | 实际编辑用时，允许小数，直接确认可填 0。 |
| 事实错误数 / 事实问题 | 完成核对后填写错误条数，可为 0；若有，写明哪句话与哪条资料不符。 |
| 实拍返工镜头 | 实拍后写镜号与原因；实拍无返工填“无”。 |
| 两稿偏好 | 同一编号任一行填 A、B、相当、均不选之一。 |

“本轮未交付稿件”的行保留并留空。编号、稿件代号和列名保持原样。当前工具按一位编辑的一张评分表汇总，多位编辑各填一份，可分别出报告。

## 看结果

```sh
python3 scripts/blind_review.py report runs/review-01/private-key.json runs/review-01/ratings.csv > runs/round-01/quality.json
```

优先看留出组 `both_outcomes_known`、`complete_pairs` 和偏好票。两版均交回评判或明确生成失败，才进入成对比较。`all_cases` 同时展示全部简报、生成失败数、已评数、评审覆盖率。可发布率按已评分稿计算；两版比较还可看按全部已提交简报计算的可发布率和首稿可确认率，未完成相应评分时返回 null。编辑分钟给出中位数和实测篇数，事实错误与实拍返工同时给出核对或实拍篇数。两篇都被放弃、只有一版生成、两版都没有生成的情况都能保留。

每份生成归档可在 `usage` 提供 `attempts`（生成批次总尝试数，含初次、失败重试和备用模型）、`input_tokens`、`output_tokens`、`actual_usd` 和 `estimated_usd`。每项填整批合计，包括归属该次试验的失败重试和定向返工。美元按账单与费率估算分别填写，服务积分和预算预留不填入这两项。同一笔费用只归入一个简报的一次版本运行。报告分别显示观测数、覆盖率和已知小计；仅在费用全量归集、全部已生成稿件完成发布意愿评分且至少一篇可发布时，才给出该口径的每篇可发布成本。
