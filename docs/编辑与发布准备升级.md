# 编辑与发布准备升级

日期：2026-10-08

## 本轮落地

- 我的创作优先展示最新待发布批次的一篇推荐稿，以及最多两个不同“方向 + 切角”的备选。其余稿件及历史内容完整保留、可展开；生成数量、积分与导出范围不变。
- 推荐依据为基础交付检查、待补项数量、已有封面和仍存在的关联照片。说明可见，不声称预测内容效果。没有正式检查的历史稿不会获得“检查通过”标签。
- 单篇编辑标题、正文、话题、封面文字、开头、行动引导和已有评论布局，同步展示正文预览。可复制当前正文、下载 TXT，以及进入现有封面工作台。
- 保存与恢复版本均免费。首改保存初始版本 0；每次有效修改或恢复增加版本，旧版本可查看和恢复。不改变稿件 ID、生成批次、收藏状态或已保存封面。
- 未保存编辑在当前标签页保存 24 小时，按账号、项目和稿件隔离，退出登录清除。存储失败会明确提示及时保存；跨标签页以服务器版本号防止覆盖。恢复前须保存未提交修改。
- 手动修改时隐藏旧的检查结论；保存后检查当前公开文案的占位内容、标题及行动引导等基础问题。手动改稿使用“已编辑，请核对后发布”，不会沿用事实核验或效果保证。原始依据与制作提示保留供参考。
- 已发布或已记录效果的稿件只读，避免将历史效果错误关联到新文案。历史版本仍可查看，正文仍可复制。
- 发布效果汇总默认折叠，保留工序筛选；编辑入口提前到稿件标题下。

## 接口与数据

- `creation_revisions`：按稿件 ID 和单调递增版本号保存内容快照、动作说明、时间；初始化时创建，不重写现有稿件。
- 工作区返回稿件 `revision`，未编辑稿件为 0。
- `GET /api/creations/{id}/revisions?project_id=...`：当前项目中未删除稿件的版本。
- `POST /api/creations/{id}/edit`：`project_id`、`revision`、`changes`。只接受可编辑字段，元数据不可改；版本冲突返回 409。
- `POST /api/creations/{id}/restore`：`project_id`、`revision`、`restore_revision`。事务内追加恢复版本。
- 所有读写先校验项目权限、稿件所属项目及软删除状态；保存使用事务串行化版本校验和更新。

## 验证与边界

- 162 项 Python 测试通过，包含新增的 8 项编辑/恢复、权限隔离、并发覆盖、导出、积分不变及质量标记回归。
- 前端状态测试和新增创作流程测试通过：推荐批次与角度去重、完整保留、正文复制、暂存隔离与过期、字段顺序不造成误报修改。语法检查通过。
- 独立演示数据库的真实浏览器流程验证：生成 8 条 → 推荐稿 → 修改并保存 → 恢复初始稿 → 未保存修改刷新后找回 → 保存。390 像素视口检查无横向溢出（页面与编辑器各自 scrollWidth 等于 clientWidth）。
- 尚未实现整组图片自动生产、AI 局部重写、平台自动发布、平台效果自动归因或商业效果验证。预览不是平台真实发布页面。封面不会随正文修改自动重绘，需在封面工作台另存版本。
- 本轮未调用付费模型或数据源，未修改用户业务数据库；真实内容质量与留存提升仍须通过目标用户实际发布验证。
