# Daolook：从出稿工具到业务内容助手

## “更好的输出”的定义

用户用自己的业务资料，花更少的钱和修改时间，得到能发布、能让目标客户理解价值，并带来本次目标行为的内容。

不能把“写了八篇”“文案很像爆款”“模型自评分很高”当成成功。用户真正付费购买的是更容易获得有效关注、咨询和成交的能力。三种目标必须分开判断：高浏览但没有目标客户，不一定是好生意内容；少量浏览带来真实订单，也可能是更好的输出。

| 用户选择 | 内容要完成的事 | 发布后的主要判断 | 同时检查 |
| --- | --- | --- | --- |
| 更多人看到 | 让相关的人愿意停留，获得具体收获并愿意分享 | 同账号、同平台、同观察期的浏览变化 | 收藏、分享、目标人群相关性；不能用泛流量替代 |
| 更多人咨询 | 回答具体疑问，降低联系和表达需求的门槛 | 有效咨询数；每千次浏览带来的有效咨询 | 咨询是否匹配业务，单条内容制作及推广成本 |
| 更多人下单 | 解释适用对象、真实优势与购买顾虑 | 订单数、每千次浏览带来的订单 | 毛利、退款、归因与获客成本 |

有效咨询：对业务有明确需求、提出具体购买或服务问题的潜在客户；不把泛评论、抽奖留言和无效联系方式算作客资。本期只记录数量和问题摘要，不采集客户联系方式。

这些是内部产品验收标准，不在客户主流程里展示公式、原理或策略模型。客户看到的流程是：**选目标 → 给资料 → 帮我写好 → 核对并发布**。

## 本次已落地

1. **资料创作成为默认入口。** 用户选择“更多人看到 / 更多人咨询 / 更多人下单”，填写产品或服务名称，粘贴或上传业务资料。参考拆解、语气要求和搜索词折叠；保留原有参考创作能力。
2. **目标进入生成链路。** API 验证目标、任务保存目标、模型收到对应行动要求、成稿保存目标，“再来一批”沿用目标。默认“更多人咨询”。更多人下单但没有真实购买入口时，先邀请咨询，不虚构店铺、优惠或库存。
3. **业务事实与参考写法分离。** 所有创作模型的系统消息追加交付约束，优先于旧提示词的冲突规则；用户业务事实只来自所选资料。旧 Skill 版本和管理员配置保留，不自动覆盖。
4. **交付检查。** 检查公开文案及评论中的占位符、标题长度、受众/价值/行动说明、行动是否写入正文、文字依据的资料 ID 与原文匹配；未解决问题在正文前显示，复制按钮注明“待完善稿”，可返回补充资料重新生成。检查通过也只称“基础检查通过，请核对后发布”。
5. **引用造假和重复拦截。** 有引用但引用不匹配时拒绝模型结果，沿用已有有限重试并提供具体修正原因；同批标题和正文不能只是标点、空格、大小写不同，重复历史标题也不能通过真实生成校验。
6. **内容与制作说明分开。** 复制只包含标题、正文和标签，避免把钩子、分镜、拍摄清单、运营说明一起发出去。配图和评论回复可按需展开。
7. **真实效果反馈。** 支持手动填写浏览、有效咨询、订单、推广花费和问题摘要；未知留空，真实零值保留。看板展示已记录结果，演示稿件不参与效果汇总。CSV/XLSX 含目标、检查状态、缺项和效果记录。
8. **历史效果进入下一次创作。** 只使用当前项目、同平台、同目标、未删除且标记已发布的正式稿件记录，最多 12 条；包含发布时间、记录时间和花费。明确标记为用户手动记录，不将相关性当因果或效果承诺。

## 本次修复的具体问题

- 旧规则允许把参考内容中的产品事实迁移到用户业务：追加系统级边界；真实模式无自有资料的再创作在计费前拦截。
- 模型结构重试不知道错在哪里：在原有重试次数内返回具体交付检查原因，不另起无限重写循环。
- 只比较正文原始字符串，标点变化即可冒充新稿：增加规范化去重与真实生成的历史标题校验。
- 复制正文混入制作与运营说明：只复制公开发布部分。
- 只用临时资料创作后，“再来一批”丢失依据：继承最后成功任务的未过期资料，忽略失败任务；即使后台清理尚未执行，复用时也检查保留期限。过期且无其他资料时，在冻结积分前提示补充。
- 切换项目后沿用上个项目的表单草稿：按用户及项目分别保留草稿，切换时恢复各自资料；过期或退出账号后清除，防止误用。
- 自主主题可能被传进参考再创作接口：明确拒绝，避免错误的创作路由。
- 主题和搜索词的非法类型曾被强制转换为文字：现在返回输入错误。
- 固定“点击率 20% 就适合投放”被重复展示：移除客户界面和导出的统一阈值，生成约束明确不使用这一阈值。

## 能验证什么，不能验证什么

本期引用校验能证明“引用短句存在于本次所选文字资料”，**不能证明整篇文案所有陈述都真实、引用支持了所有结论，或者业务资料本身真实**。图片也不能证明产品功效。没有文字依据、依据不足的内容会标为待补充；不伪装成完整事实核验。

批量结构与重复检查不等于判断创意好坏；交付检查不预测点击率或爆款概率。手动效果记录未经平台认证，不能据此保证因果、ROI 或下次必然有效。当前数据是累计快照，不是事件明细；没有自动归因、订单去重、退款或毛利统计。

演示模式用于体验操作；真实模型、TikHub 和平台实际效果必须分别验收。本轮不调用付费生产服务，不修改用户生产数据库。

## 后续升级顺序与验收建议

### 第一优先：减少用户补资料、改稿和挑稿的时间

- 资料入库时整理“卖给谁、卖什么、可信证据、常见顾虑、购买路径”，每条事实保留出处及更新时间。
- 同一次只问真正阻止成稿的一个问题；能省略的缺失信息就省略。处理互相冲突的价格和过期优惠时再向用户确认。
- 下一版在后台生成候选，默认交付少量实质不同的成稿；不要为了凑 6–8 条制造重复内容。先验证每种目标最有用的交付数量，再改变计费与批量接口。
- 支持就地改稿、单条定向重写、可恢复的历史版本，避免补一个事实就整批重做。

建议验收：用户拿到第一条可用内容的时间、修改时长、生成后实际发布比例、每条可发布稿的真实模型成本。先测现有基线，再制定降幅，不预设已实现的提升数字。

### 第二优先：让结果反馈更可信

- 按授权接入平台曝光、点击、私信和店铺订单；设计去重与归因窗口，分开自然和付费流量。
- 对比同一账号、相近题材、相同观察期，结合有效咨询、订单、毛利和退款；不拿发了一个小时的内容跟积累一年的内容比较。
- 只把反复有效的选题和表达方式沉淀为偏好，保留探索方向，避免永远复刻一条偶然高数据的内容。

### 第三优先：验证“比旧版更好”

- 选取真实业务样本，覆盖实体零售、到店服务、专业服务等场景；将资料充分和资料不足的情况分开。
- 同一份资料分别用新旧链路生成，盲评是否事实准确、兑现标题、容易理解、易于制作、行动明确；记录人工改稿时间和成本。
- 在真实账号做分组发布试验，预先确定目标与观察期。不能只挑高数据案例宣称有效，也不以合成样本证明流量提升。

本次完成的是上述效果导向产品的第一轮实现；实际流量、有效客资和成交提升要用真实发布后的数据证明。
