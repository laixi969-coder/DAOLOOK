# 真实问题、选题依据与发布反馈

日期：2026-11-07

## 用户流程

沿用「选目标 → 给资料 → 创作 → 核对发布 → 记录效果」，不增加必填步骤，也不增加单独的模型调用或积分项目。

- 国内自主创作、参考再创作和海外创作都有折叠的「最近客户问过什么？」入口。可只写一句话；默认标为商家转述，也可选择客户咨询原话、现场观察、自有评论、同行评论、搜索记录、市场话题、待验证想法。场景、出处、发生日期均可不填。
- 问题随创作任务成功入队，在同一事务中存入当前项目；余额不足、队列已满等提交失败不留下半条记录。重复提交同一记录不会增加记录数量，更不会推算频率或人数。入队后清空已提交的问题输入，避免以后把已修改的记录恢复成旧文字；业务资料草稿保留。
- 折叠入口内可查看、补充、修改、删除已有记录，无须建立新的侧栏工作台。每页 20 条，每项目最多 500 条；用户输入留存在原有按账号和项目隔离的标签页草稿中，24 小时到期。
- 每篇新稿件有「为什么写这条」折叠区，展示具体问题或主题、相关人群和场景、核心答案、观众收获、切入方式、问题出处以及单独的回答引用。没有问题证据时明确显示待验证；市场/资料线索和演示内容分别标识。
- 稿件卡恢复已有的「发布与反馈」入口。用户仍在原来的效果表单填写累计指标和「客户问了什么」，不必把追问再次录入问题库。未知指标留空，真实的零保留。
- CSV / XLSX 在原有字段之后追加选题状态、选题依据、问题出处、回答依据。复制发布文案仍只复制标题、正文、标签。

## 来源和答案分开

`question_observations` 是项目私有的原始记录表，保留来源、原话/观察、场景、出处、发生日期及记录时间。它不属于业务事实资料，也不会自动成为证明产品功效或服务承诺的 evidence。

生成模型收到单独的 `question_observations` 输入，每条返回 `topic_plan`（problem / relevance / answer / takeaway / approach / refs）。refs 中的 ID 必须来自本次输入，quote 必须逐字连续出现在对应原文中；伪造来源、跨项目引用、重复引用或缺失策划字段进入既有有限重试和失败退款流程。业务回答仍由已有的 `evidence` 引用本次 assets。

`topic_basis` 的来源元信息与状态由服务端根据已校验引用生成，忽略模型自行提供的“已验证”状态。状态分为：演示、有来源记录、资料/市场线索、探索假设。“有来源记录”不代表自动核验了用户身份、需求普遍性、问题动机或整篇答案。

系统说明要求先判断相关性、确定可兑现的核心答案，再写标题。比较/反差/风险说明/判断/答疑/故事/展示是可选角度，不强行凑齐；解释风险而非夸大风险。海外沿用原有三方案、分镜、语言和创意规则，不强制转成答疑，保留故事和展示。

## 自动复用和反馈回流

提交时自动从以下来源构建最多 12 条候选，保存为本次任务输入快照。自动候选按剩余输入预算裁减，不因检索到更多记录而要求用户精简原本合法的业务资料：

1. 本次填写的问题优先；当前项目已有记录按主题词相关性和记录时间筛选。相关性使用中英文词片段规则，只是召回线索，不是质量评分；少量近期记录用于补充语义候选，模型仍须判断相关性，可以不引用。
2. 所选资料已整理的「常见顾虑」可作为资料线索，必须是非演示要点且原文仍能在当前所选文字资料中找到；不升级为真实客户提问。
3. 已发布、未删除、非演示稿件的当前问题备注。先排除没有备注和演示稿，再取近期记录。问题可以跨目标复用；效果指标只走原有同平台、同目标的 `history_results` 通道，不混进问题候选。

反馈直接读取 `creation_results` 与发布状态，不复制成不断累积的记录，不产生重复计数。覆盖备注、清空备注、撤回发布、删除稿件，均影响之后提交任务的候选。已经入队的任务和历史稿件保留当时快照；这允许追溯当时的依据，不代表后续仍使用已删除的记录。

海外反馈按稿件实际 `target_platform` 区分；三平台创作可读取三个海外平台的反馈，国内创作不会把它们当作同平台反馈。

手动编辑和 AI 重写保留原始选题依据并标记需重新核对；模型不能借重写替换成伪造的已验证来源。恢复历史版本沿用现有版本机制。

## 工程边界

- 启动自动创建 `question_observations` 表及索引；不改写历史稿件、不猜测历史问题来源。运行中的服务需重启加载新代码和迁移。
- API：`GET /api/questions?project_id=...&offset=...`、`POST /api/questions`、`POST/DELETE /api/questions/{id}`。创建和修改使用 `observation` 对象；沿用现有项目鉴权、请求大小、存储额度。
- 账号删除覆盖新表；任务的 observation/question_context 快照按现有临时资料期限清理，项目保存记录和稿件已引用的历史快照不随此清理。
- 没有接入新的平台评论抓取、私信授权或全网监听。客户原话、评论、搜索记录由用户提供；市场标题和评论数量不冒充已读到的真实提问。
- 引用匹配只证明文字出处，不做语义真实性或因果证明，不预测爆款概率。实际模型质量、发布后咨询和成交仍需真实业务验证。

## 验证

专项回归覆盖来源类型与长度校验、重复保存、修改删除、分页、事务回滚、跨项目隔离、问题与回答依据分离、伪造来源退款、资料原文更新、演示排除、反馈覆盖/清空/撤回/删除、海外平台归属、编辑后失效提示、任务清理和账号删除。

前端回归覆盖可选输入提交、草稿隔离、提交成功后清空已保存输入、来源文本转义、复制不混入依据、发布/反馈按钮、切换项目时丢弃旧请求、国内参考创作及海外入口。

浏览器使用独立临时数据库验证：填写来源和场景 → 生成演示稿 → 展开依据 → 标记发布 → 回填追问 → 查看并修改问题记录。390px 手机布局没有横向溢出，控制台未出现错误。演示反馈未进入真实问题候选。

真实模式生成链路使用受控模型替身验证模型输入、结构校验、来源解析和计费退款；未调用真实付费模型或平台服务，不能将这些测试解释为实际获客效果提升。

本轮最终结果：314 项 Python 测试通过；3 个 Node 前端套件通过（交互回归 25 项）；`npm run check` 和 `git diff --check` 通过。新增 15 项 Python 专项与 7 项前端交互回归。海外旧测试的「所有区域不得折叠」调整为「创意交付保持展开，仅发布与反馈折叠」，保留原有内容直接可见的约束。
