# DAOLOOK 对抗式审查与修复

日期：2026-09-23。基线：37a0c6e。本次是代码审查与本地对抗回归，不是第三方渗透认证。

## 检查的不变量

1. 任务必须属于提交用户的项目，积分冻结、退款、结算必须保持一致。
2. 一个任务最多被一个工作线程领取；终态不可被迟到结果改写。
3. 执行时使用用户提交时确认的资料，不能静默换成后来编辑的内容。
4. 原始平台指标、来源和演示标记属于可信数据层，模型只能提供分析文本。
5. 无效输入不得进入付费队列；外部服务不得借重定向接收其他供应商的认证信息。

## 已修复问题

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| 任务领取不是原子操作 | 两个线程可能同时看到 PENDING，重复调用外部模型；数据库余额约束虽能阻止负冻结额，不能阻止重复外部执行 | 事务内条件更新 PENDING → PROCESSING，只有成功领取者执行 |
| 结算仅排除取消 | 已失败退款的任务仍尝试保存和扣冻结额，触发约束异常；其他任务仍有冻结余额时可能污染余额 | 保存与结算前排除全部终态 |
| 模型覆盖平台事实 | 分析输出附带 source 字段，可篡改点赞数、平台、演示标记 | 删除额外 source，禁止合并进原始内容 |
| 排队期间素材变化 | 上传后修改或删除资料，执行时实际使用的资料与提交时不同 | 冻结积分的同一事务内校验并快照所选资料，执行读取快照 |
| 服务层缺少项目归属检查 | HTTP 层虽有权限校验，内部调用提交函数仍可跨用户项目写入任务 | 积分事务内再次校验项目所有权 |
| 删除稿件后产生迟到封面 | 生成完成前稿件已软删除，仍可能扣费保存无主封面 | 保存事务内重新检查稿件，失败走原退款流程 |
| 排队任务随全局模式切换 | 演示任务可能突然进入真实数据获取流程 | 提交时固定 execution_mode；不锁定供应商、密钥或技能版本配置 |
| 非对象 JSON 与错误字段类型 | 数组等请求触发 500，错误创作参数可能先扣费再失败 | 请求根必须为对象，文本长度和类型在提交前检查 |
| 无效管理员配置 | limits 为数组、重试次数为小数等造成运行时失败 | 嵌套配置对象、整型范围、布尔冒充积分的校验 |
| 非有限指标污染评分 | Infinity 被计算成满分，负数和布尔值被当作有效数据 | 忽略非有限、负数与布尔指标；拒绝 JSON NaN/Infinity |
| 带认证请求自动重定向 | 标准 HTTP 客户端可能将 Authorization 带到重定向目标 | 外部 JSON 客户端拒绝重定向，要求配置最终 HTTPS URL |
