# 上线检查清单

当前实现是单机版：Python 标准库 HTTP 服务 + SQLite + 进程内两个工作线程。适合本机与小团队单实例使用。下面分两部分：单机上线前必须完成的，以及用户量上来后需要改造的。

本清单的旧架构缺口以 [2026-10-23 修复说明](2026-10-23-工程审查修复.md) 为准：凭证已移出数据库、管理员已有操作审计、费用与资源已有上限。定时备份、异地恢复和真实监控仍需部署验收。

## 一、单机上线前（必须）

- [ ] 用 HTTPS 反向代理（Caddy / Nginx）对外，服务只监听 127.0.0.1；设置 `DAOLOOK_SECURE_COOKIE=1`。
- [ ] `.env` 与 `data/` 目录权限设为仅服务账号可读写（`chmod 600 .env`、`chmod 700 data`）。
- [ ] 管理员密码 ≥ 12 位，且不与其他系统复用。
- [ ] 后台切换为「真实服务」，确认演示入口已关闭。
- [ ] 配置邮件服务并「发送测试邮件」，确认注册验证码、旧账号验证开通、找回密码可用；白名单不代替验证码。
- [ ] 配置 TikHub Key，用小红书图文、小红书视频、抖音视频各一条真实链接「测试参考链接」。
- [ ] 确认旧账号在后台已明确开通真实服务；生成演示账号不能转正。
- [ ] 配置各供应商真实费用上界及账号/全局日预算，确认超限会阻止新调用。
- [ ] 配置文本模型主备路由，「连接测试 / 同步模型」通过；如需自动转写口播，配置转写模型并用一条抖音链接验证。
- [ ] 在「Skill」页测试并发布创作 Skill v5（小红书、抖音各一条）。
- [ ] 用 30–50 条真实样本运行 `scripts/validate_samples.py`（字段提取）与 `scripts/calibrate_ranking.py`（排序校准），把建议权重人工确认后保存。
- [ ] 设置每日备份：`python3 scripts/backup_db.py --keep 30`，并演练一次从备份恢复。
- [ ] 只运行一个服务实例：同一个 SQLite 上启动多个实例会导致重启恢复时把对方的任务误退款。

## 二、用户量上来后（改造项）

| 现状 | 瓶颈 | 建议 |
| --- | --- | --- |
| SQLite 单文件 | 写并发、无法多实例 | 迁移到 PostgreSQL；表结构基本可平移，积分冻结改用行级锁 |
| 进程内队列 + 2 个线程 | 重启即中断，退款后需用户重提 | 换成持久化队列（Redis + RQ / Celery），任务可恢复、可限流 |
| 私有文件存凭证，数据库只存引用 | 文件存储不等于磁盘加密 | 按部署需要接入云 KMS / Vault；凭证目录单独安全备份 |
| 管理操作已有审计 | 单机数据库审计仍可被系统管理员修改 | 按部署需要异地保存审计与定期查阅 |
| 标准库 HTTP 服务 | 无连接池、静态资源性能一般 | 换成 ASGI 框架（FastAPI）+ Uvicorn，静态资源交给反向代理 |

这些改造不改变产品行为，可以在确认有真实用户规模后再排期。
