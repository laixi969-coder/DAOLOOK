# 2026-10-23 工程审查的 10 项修复

本次修复针对审查报告的 F01–F10，不把当前产品没有的企业 SSO、支付或医疗流程加入产品。主体仍是单实例 SQLite，不支持两个服务同时打开同一业务库。所有新增组件均使用 Python 标准库。

## 管理员与凭证（F01/F02）

- `DAOLOOK_ADMIN_EMAIL/PASSWORD` 仅用于首次创建管理员。已有管理员启动时不会覆盖密码，也不会将同邮箱普通账号自动提升为管理员。后台密码重置仍立即撤销该用户所有会话。
- `.env` 读取时设为 0600；新建专用数据库目录设为 0700；已有目录必须为 0700，否则拒绝启动且不改动其权限；数据库、WAL、SHM 设为 0600。数据库必须使用专用目录，不放项目根目录、HOME 或根目录。
- 新保存的 API Key 和 SMTP 密码进入默认 `data/secrets/` 的私有文件；SQLite 中只保存随机引用。可通过 `DAOLOOK_SECRETS_DIR` 使用单独挂载的凭证目录。已有明文配置会在初始化时迁移。凭证文件内容与目录项均同步磁盘后才提交数据库引用。
- 该私有文件存储提供文件隔离，不提供磁盘加密，也不替代云 KMS。原历史备份可能包含迁移前明文，需按既有备份保留策略保护、到期销毁；涉及真实泄露时须在供应商侧轮换凭证。
- 日常数据库备份不含私有凭证文件。部署/迁机须单独安全备份与恢复凭证目录，且只允许服务账号访问。恢复历史数据库需要对应的历史凭证文件，因此不会自动删除尚可能被备份引用的文件。

## 取消、搜索和赠送积分（F03/F04/F05）

- 真实任务仅在 `PENDING` 排队阶段允许取消退款。任务被 worker 原子领取后不再取消；执行失败仍按原规则退用户积分。供应商预算不会因为用户退款而释放。
- 海外搜索返回 `202` 与 `task_ids`，进入同一有界队列，默认冻结 1 积分。成功后结算；15 分钟缓存命中全额退回；失败退款。前端任务记录可查看结果。全部搜索结果、缓存与积分结算同事务提交；任一失败全部回滚后退款。积分价格可以通过后台配置。
- 真实模式注册必须通过邮箱验证码；白名单只限制注册范围，不能替代邮箱归属证明。SMTP 未启用时暂停真实注册。演示模式继续支持本地体验注册与演示用户。
- `live_accounts` 持久记录正式使用权限，切换模式不会自动批准旧账号。生成的演示身份永久不能调用付费服务；旧普通账号可以在账号面板验证邮箱，或由管理员明确开通。开通默认清零未经核验的旧体验余额，不重复赠送欢迎积分；管理员可在开通弹窗明确勾选保留原余额。所有批准和余额调整同事务审计，迁移本身不删除原余额。
- 新注册真实用户的赠送默认每天合计最多 1000 积分、整个数据库累计最多 10000 积分；超出预算可注册但赠送为 0。环境变量分别为 `DAOLOOK_SIGNUP_DAILY_CREDITS`、`DAOLOOK_SIGNUP_TOTAL_CREDITS`。不要把这些额度当作反机器人身份认证。

## 费用与资源预算（F08/F09）

真实付费调用（包括演示模式下管理员发出的真实连接测试）必须配置 `DAOLOOK_EXTERNAL_PRICES`，缺失或价格不完整时停止调用，不猜测供应商价格。配置中的金额单位均为**整数微美元，1 美元 = 1000000 微美元**。

JSON 配置键：

- `model:<provider_id>/<model_id>`：文本模型；默认供应商的 provider_id 为 `default`。
- `tikhub`：数据源每次调用。
- `transcribe:<model_id>`：转写每次调用上界，须覆盖最大允许的 25 MiB 媒体请求。
- `image:<provider_id>/<model_id>`：旧图像适配器每次请求上界；当前本地封面不使用该服务。

文本价格字段为 `input_per_million`、`output_per_million`，单位为每百万 token 的微美元；有图片时必须提供 `per_image`（单张图片最坏费用上界）。其他调用需要 `per_call`（单次最坏费用上界）。价格必须包括供应商实际费率、图片规格、附加费用和必要安全余量。示例仅演示格式，**不是任何供应商真实价格，不能直接作为计费依据**：

```dotenv
DAOLOOK_EXTERNAL_PRICES={"model:default/your-model":{"input_per_million":1000000,"output_per_million":5000000,"per_image":100000},"tikhub":{"per_call":10000}}
DAOLOOK_USER_DAILY_BUDGET_MICROUSD=2000000
DAOLOOK_DAILY_BUDGET_MICROUSD=20000000
```

- 默认每账号每天预留上限 2 美元，全局每天 20 美元，按 UTC 日期重置。每个外部请求（含重试和备用模型）开始前以 SQLite 写事务原子预留，达到预算即阻止。
- 文字输入按 UTF-8 字节加消息框架估算保守 token 上界，另加图片上界和 8192 个最大输出 token。预留金额不因超时、失败、取消或积分退款而减少，防止未知账单被当成免费。
- 同时保存供应商返回的输入/输出 usage，但后台“费用预算”展示的是保守预留，不是供应商实际账单。准确的硬金额保证取决于运营方提供正确价格上界；供应商侧仍应设置账户硬额度。
- 每任务最多 12 份资料、6 张图片；文字资料每份最多 100000 字，任务合计文字输入最多 120000 UTF-8 字节，实际模型消息含框架最多 140000 字节。超额在发出付费请求前拒绝。
- 每账号最多 500 份资料、50 个项目；默认业务内容及任务记录配额 100 MiB/账号、1 GiB/全局，磁盘少于 128 MiB 时停止新增大内容。可配置 `DAOLOOK_USER_STORAGE_BYTES`、`DAOLOOK_TOTAL_STORAGE_BYTES`、`DAOLOOK_MIN_FREE_BYTES`。
- 存储统计覆盖资料、参考及分析、成稿及效果/发布清单、封面、历史版本、海外收藏/搜索缓存和任务输入/结果/错误；任务结果、原始简报及赛道参考在事务提交前按实际内容检查；不等同于整个文件系统用量。日志、备份、凭证目录仍应在系统层设置磁盘告警、日志轮转和保留策略。
- 工作区默认每类 25 条、最多 50 条，使用 `(created_at,id)` 游标翻页；前端有“加载更早的内容与更多资料”。筛选和统计会明确提示基于已加载记录。
- 私有图片从认证媒体接口按需读取，不再在列表 JSON 中携带 base64；文字资料列表只给前 1000 字预览，完整原文从详情接口读取。已加载页数在刷新后保留，跨页资料选择和历史任务详情按需补读；历史 HTTPS 封面保持直接打开。完整资料/稿件/参考可按 ID 读取且仍检查项目归属。任务/积分/审计列表支持时间+ID游标；导出仍可导出项目完整成稿。

## 备份与恢复（F06）

应用与脚本共用 `.env` 和相对于项目根目录的数据库路径规则。脚本以只读模式打开已存在的源库；空库、损坏库、业务表缺失或外键错误会失败，不发布备份或删除旧备份。成功快照先写临时文件、校验、同步磁盘，再原子发布并轮转。备份发布与轮转持有目录锁，并发调用不会互删；源库在同一读事务中校验和快照。目标存在旧 WAL/SHM/journal 时拒绝恢复。已有备份/凭证目录也必须为 0700，脚本不会改动共享目录权限。备份名含微秒，`--keep` 必须 >= 1。

每日执行（仍需由实际部署环境配置定时器和异地保存）：

```bash
python3 scripts/backup_db.py --keep 30
```

恢复演练必须使用**新目录**，不能覆盖运行中的数据库：

```bash
python3 scripts/backup_db.py --restore data/backups/daolook-时间.db --db data/restore-drill/daolook.db
```

服务恢复步骤：

1. 停止唯一服务实例，保留当前库及 WAL/SHM 作为故障证据。
2. 用上面命令恢复到新目录，恢复对应的私有凭证目录；限制所有目录和文件权限。
3. 将 `DAOLOOK_DB` 指向恢复库、`DAOLOOK_SECRETS_DIR` 指向恢复的凭证目录。保留原文件，不直接覆盖。
4. 在内网启动，检查登录、项目、稿件、余额及流水，核对备份时间之后允许损失的内容。启动会给未完成任务退积分，不会重新发出这些付费请求。
5. 验收后再恢复流量；失败则停止新实例并恢复原配置。记录恢复用时、备份时间与业务核对结果。

本次自动回归做了隔离数据库备份/恢复/完整性和用户数量校验，不代表已完成真实生产故障演练或异地备份。

## 工作线程与审计（F07/F10）

- 任务执行失败后，数据库退款暂时失败会以 0.1 秒起、最多 5 秒间隔持续重试幂等结算。不会杀死 worker，也不会重新发出原付费调用。
- `/api/health` 检查数据库可读、预期 worker 是否存活和是否存在结算故障；异常返回 503。部署方应把该接口接到实际监控，不能把接口存在当作已经有人收到告警。
- 后台新增操作审计和费用预算页。管理员改密、积分调整、服务配置、供应商、路由、任务重试及 Skill 变更记录操作者、目标、时间、请求 ID 与脱敏摘要，与相应数据库写操作同事务提交。
- 请求日志输出 JSON，含请求 ID、账号、HTTP 方法、状态和耗时；不写请求正文、查询串、密码、Key。通用错误提供参考编号。任务故障日志以任务 ID 关联，不把外部错误对象或调用正文输出到日志。
