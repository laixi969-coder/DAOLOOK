# DAOLOOK

基于《社媒爆款拆解与再创作平台_完整产品PRD》V1.1 实现的本地全栈应用。奶油白、荧光黄绿的中文工作台，支持桌面与手机。

核心流程：**找依据 → 平台专属拆解 → 每次追加 3 条稿件 → 可选封面 → 复制 / Excel / CSV 导出**。

## 启动

需要 Python 3.9+。应用运行不依赖 pip 或 npm 第三方包。

```bash
cd /Users/caiwenbin/Daolook
./run.sh
```

打开 http://127.0.0.1:8000 。也可执行 `npm run dev`。Node 仅用于可选的脚本入口和前端语法检查。

默认是**演示模式**。首次访问创建独立的演示用户，赠送 300 演示积分，提供 6 条本地插画示例。数据保存在 `data/daolook.db`，重启保留；其他浏览器会得到不同的用户空间。演示拆解、稿件和 SVG 封面均有标识，不代表真实平台数据或 AI 输出。注册的邮箱账号初始获得 100 积分。

## 管理员

复制 `.env.example` 为 `.env`，填写自己的管理员邮箱和至少 12 位密码，再启动或重启服务：

```dotenv
DAOLOOK_ADMIN_EMAIL=your-admin@example.com
DAOLOOK_ADMIN_PASSWORD=填写至少12位的强密码
```

左下角账号按钮 → 切换账号 → 使用管理员邮箱密码登录，侧栏会出现「管理后台」。没有内置通用管理员密码。`.env` 会在启动时读取，外部环境变量优先；配置的管理员密码会在启动时应用到指定账号。

管理后台可操作：

- 用户列表、人工发积分、逐用户积分流水。
- 任务与错误、失败任务重试，重试重新冻结积分。
- TikHub Base URL、Key、端点、参数与请求方法、参考链接连接测试。
- 默认模型及多个附加供应商、启停、模型列表同步与连接测试。
- 拆解 / 创作 / 封面各自的主模型和备用模型，支持跨供应商。
- Skill 草稿、结构测试、发布、回滚到已发布历史版本。
- 积分价格、批量上限、超时、模型重试次数、临时资料存留时长、相对表现排序权重。

## 接入真实服务

1. 登录管理后台，填写 TikHub API Key。
2. 填写兼容 OpenAI HTTP 协议的模型服务 Base URL、Key、文本模型 ID 和图像模型 ID。
3. 保存，再运行接口测试 / 模型同步。文本使用 `/chat/completions`，旧图像适配器保留 `/images/generations`（新封面工作台使用本地排版，无需图像模型），模型列表使用 `/models`。所选图片资料作为多模态消息发送，需选择支持图像输入的文本模型。
4. 在「模型路由」分别配置三类任务的主备模型；留空模型 ID 使用默认配置。
5. 将运行模式改为「真实服务」。此时关闭新建演示账号入口，外部请求失败会显示错误并退还积分。

服务设置保存在数据库。`DAOLOOK_MODE` 只决定**新数据库**的初始模式；已经初始化的数据库请在后台切换模式。

TikHub 端点在 `server/defaults.py` 集中定义，后台可覆盖。例如：

```json
{
  "douyin_search": {
    "path": "/api/v1/douyin/search/fetch_video_search_v2",
    "method": "POST",
    "params": {"keyword": "{text}"}
  }
}
```

支持 `{text}` 和 `{user_id}` 参数替换。小红书图文/视频使用 App V2；抖音内容使用 App V3，搜索使用独立 POST 搜索接口，博主主页先解析 `sec_user_id`。关键词 / 博主入口当前每次精选最多 3 条返回结果。所有指标直接从数据源响应提取，不由模型编造。

核对依据：

- [TikHub 小红书 App V2 指南](https://blog.tikhub.io/zh/article/7)
- [TikHub 官方抖音端点说明](https://github.com/TikHub/tikhub-plugin/blob/main/skills/douyin/SKILL.md)
- [TikHub 官方 SDK 接口索引](https://github.com/TikHub/TikHub-API-Python-SDK/blob/main/docs/reference.md)

接口仍需使用实际账号验证配额、权限和最新返回结构。当前交付环境没有外部服务密钥，**未进行真实 TikHub、文本模型、图像模型的端到端调用，也没有完成 30–50 组真实样本校准**。

## 已实现的产品行为

| 范围 | 实现 |

| 登录 | 邮箱 + 密码注册登录，PBKDF2 密码哈希，HttpOnly / SameSite 会话，登录频率限制 |
| 项目 | 新建、切换、用户及项目访问隔离 |
| 参考入口 | 单链接、逐行批量、博主主页、关键词，自动识别链接平台 |
| 拆解 | 小红书与抖音各 10 个独立维度，先浏览后收藏 |
| 再创作 | 必须有参考；每次 3 个独立 ID，历史追加，单条复制/收藏/软删除 |
| 资料 | 新增、修改/替换、删除；品牌、产品、受众、禁用词、文本和图片；创作不自动全选 |
| 临时资料 | 粘贴或文本上传，任务完成后询问保存；后台到期清理，默认 24 小时 |
| 封面 | 内置品牌杂志 / 方法清单 / 真人冲击；免费编辑预览，单独计费保存；1080×1440 PNG/JPG 导出 |
| 导出 | UTF-8 BOM CSV、真正的 XLSX，统一字段，可导入飞书；CSV 公式注入防护 |
| 积分 | 原子冻结、成功结算、失败/取消退款、流水；余额不透支，删除成稿不退款 |
| 队列 | 两个后台工作线程，任务落库，独立状态，批量逐条结算，服务重启未完成任务退款 |
| 管理 | 用户、流水、任务重试、供应商、主备路由、连接测试、Skill 版本、系统参数 |
| 相对表现 | 互动、粉丝效率、账号/赛道相对值、新鲜度、可复用性；缺少指标时不虚构 |

## 测试

```bash
python3 -m unittest discover -s tests -v
npm run check
```

测试使用临时数据库，不修改工作台数据。覆盖 46 项测试，其中包含 40 组**合成**双平台结构样例；这些不等同于真实内容回归。覆盖项目越权、登录、批量拆解、追加 6 条稿件、软删除、Excel/CSV、封面、退款、并发余额保护、批量原子性、取消后不重复退款、临时资料清理、数据源参数映射、模型输出校验与备用路由。

## 部署边界与后续验收

当前是可运行的单机 V1.1 实现。SQLite 和内置 HTTP 服务适合本机体验和小规模单进程部署；生产上线应使用 HTTPS 反向代理，设置 `DAOLOOK_SECURE_COOKIE=1`，保护 `.env` 与数据库文件并定期备份。不要在同一个 SQLite 数据库上启动多个服务实例，启动恢复会将未完成任务退款。

- 邮箱登录目前使用邮箱密码，不包含邮件验证码、邮箱所有权验证及密码找回服务。
- 密钥保存在本机数据库，API 返回时掩码。面向公开多租户服务时需接入密钥管理及运维审计设施。
- 资料上传支持 TXT / Markdown / CSV 与 PNG / JPEG / WebP，未接 PDF / Word 解析。
- 不下载或长期保存完整原视频。不具备原始画面/音轨的内容，模型应明确标注镜头、节奏等维度无法判断；未集成独立的视频转写服务。
- 相对表现排序目前是可配置启发式；账号近期中位数、赛道基线、可复用性缺失时自动跳过。真实样本采集、基线构建与权重校准仍需数据验证。
- 未集成正式支付、自动发布、最终视频生成、团队权限和持续监控，与 PRD 的 V1 排除项一致。
- 没有部署到公网；Dockerfile 提供可选的容器启动方式，未在本环境执行 Docker 构建。

## 内置封面工作台

在「我的创作」的稿件下点击「封面」。根据稿件关键词推荐方向，编辑主标题、副标题、品牌署名；方法方向支持最多三项清单；图片从当前项目「品牌资料」选取，可调整裁切位置。真人方向必须选照片，当前保留原照片背景，不提供自动抠图。

免费预览及缩略图检查不冻结积分。点击「保存新封面」按 cover 规则收费（默认 8 积分），复用任务队列、冻结、失败退款与取消逻辑。每次保存追加新版本，已保存封面可再次编辑为新版本。浏览器将 SVG 中文排版渲染为 1080×1440 PNG/JPG 下载，字体使用本地中文字体；不同设备的字体细节可能不同。

`POST /api/cover/plan`、`POST /api/cover/preview`、`POST /api/cover` 均需当前用户拥有的 project_id 与 creation_id。生成参数 brief 包含 style、title、subtitle、points、brand、asset_id、crop。图片只接受当前项目中的内嵌 PNG/JPEG/WebP，素材在任务提交时快照，避免排队期间编辑影响结果。生成记录保留 brief、renderer 版本、素材名称及验证结果。

本期是 DAOLOOK 原创实现，未复制归藏 / 阿囤囤 / 波妞的受限模板或提示词，也未内置 Vivi 的 18 套模板。接入评估见 `docs/封面能力接入评估.md`。当前检查覆盖文案长度、换行、安全区与素材缺失，不包括人脸识别、事实自动核验或点击率预测；没有编造流量评分。组图与实际曝光/点击效果追踪尚未实现。

## 参考内容来源与分类

发现页已将全演示内容标为「拆解体验样本」，有真实内容时显示「项目参考内容」。列表来源为用户提交后已完成拆解的内容，不是自动推荐池；「刷新列表」只重新读取项目数据。真实模式的关键词/博主入口沿用 TikHub 接口，取前 3 条可识别结果进行拆解，尚未实现自动全网采集、账号基线采样或行业推荐。未配置密钥时不会发起真实检索；演示检索明确标注为预置样本。

行业与表达形式分开展示。`server/catalog.py` 使用标题优先的关键词规则给出建议分类及命中词，未匹配或并列时保留待分类；演示行业保留预设值。筛选项根据当前项目、收藏页、来源与平台下的实际内容动态生成。每张卡片可展开「来源与排序依据」，真实内容可跳转原文；新拆解记录保存入口、搜索词、数据源及获取时间。历史记录不伪造入口来源。

排序默认最近拆解；点赞排序按点赞数，粉丝效率要求完整点赞/收藏/粉丝数据，缺失值放最后。指标排序中真实与演示内容分组，避免示例数字进入真实比较。相对评分仍未校准，不是爆款概率；分类规则尚非平台官方分类，不包含项目相关性预测。

## 产品图与个人 IP 图片

创作表单可直接上传 PNG/JPEG/WebP（每张最多 2 MB，一次最多 6 张），上传后保存到当前项目并自动勾选。已选图片会作为多模态输入传给支持图片的真实文本模型；演示模式不分析图片。生成的三条稿件均记录所选图片 ID，打开封面默认带入第一张仍存在的图片。封面工作台也支持直接上传和替换图片，无需跳转资料页。上传后照片持久保存在项目资料，不属于临时文本资料。

三个封面方向均可使用实际图片，方法清单支持图片与文字并排；当前每张封面使用一张图片，可调裁切位置。原图不被重绘，不自动抠图或合成人物。保存后的封面嵌入当时的图片数据，因此删除项目图片不影响历史封面的下载；再次编辑时需选择仍存在的图片。

对抗式审查与修复范围见 [审查报告](docs/对抗式审查与修复.md)。任务使用原子领取、提交时素材快照与终态结算保护；模型分析不得覆盖原始平台指标；外部 API 重定向会被拒绝，服务地址应配置为最终 HTTPS 地址。
